# Автоматика проекта

Цель: разработчик ставит программы, входит в GitHub и пишет Claude «Начинай». Всё остальное — само.

## На компьютере разработчика
| Что | Как работает |
|---|---|
| Установка и подключение | `JOIN_HAN.ps1` (создаёт владелец): ставит программы, принимает приглашение, клонирует, определяет роль по логину (`tools/team.json`), переключает на `<буква>/start`, запускает Claude |
| Проверка и починка среды | `python tools/doctor.py` (`--fix` — поставить недостающее и поправить настройки) |
| Сборка и тесты | `powershell -File tools/build.ps1 [-Config Debug] [-NoTest] [-Run]` (после этапа E0) |
| Отправка работы | `python tools/ship.py -m "Что сделано"` — коммит → проверка зон → push в свою ветку → Pull Request |
| Русские коммиты | хук Git `commit-msg`, хук Claude, проверка в `ship.py`, CI (заголовок PR и все коммиты) |

## Хуки Claude Code (`.claude/settings.json`, общие для всех)
- **SessionStart** — определяет роль (`join.py`, если нет), подтягивает ветку к `main`, предупреждает об изменённых контрактах.
- **PreToolUse** — блокирует правку чужих зон (Edit/Write и shell: `sed`, `>`, `mv`, `rm` …), push в чужие ветки и в `main`, force-push, коммит не по-русски. Эвристика для shell не идеальна; последний рубеж — хук Git и CI.
- **Stop** — один раз за остановку проверяет чужие зоны и просит обновить `docs/progress/<роль>.md`.
- Аварийно (только владелец): `HAN_ALLOW_ZONE=1`.

## На GitHub (Actions)
| Workflow | Что делает |
|---|---|
| `repo-check` | на каждый PR: зоны владения, русский язык заголовка и коммитов, лицензии новых ассетов, метки `zone-a/b`, `contract`, `needs-owner` |
| `build` | сборка и тесты (делает A на этапе E0, файл `build.yml`) |
| `automerge` | вливает PR (squash), когда все проверки зелёные. Не вливает: `contract`, `needs-owner`, `hold`, Draft. Владелец может разрешить слияние меткой `automerge` |
| `contract-notify` | после слияния PR, менявшего `contracts/`, создаёт Issue «Контракт изменился» для остальных |
| `weekly-digest` | по понедельникам 09:00 (МСК): Issue «Сводка недели» (прогресс, влитые и открытые PR, Issues) + Telegram/Discord |
| `notify-failure` | при падении проверок или сборки — сообщение в Telegram/Discord |
| `weekly-build` | по пятницам 15:00 (МСК): Release-сборка Windows, архив в GitHub Releases (после E0) |

Настройки репозитория (squash-слияние, удаление веток после слияния, права Actions) выставляет `bootstrap_github.py`.

## Что требует человека
- Владелец одобряет PR с метками `contract` и `needs-owner` (правки интерфейсов и общих файлов).
- Конфликты слияния решает автор PR.
- Секреты Telegram/Discord задаёт владелец (необязательно).

## Ограничения
- Если на бесплатном плане нельзя защитить `main`, защиту держат хуки и CI; жёсткий запрет на сервере требует платного плана.
- Лимит бесплатных минут Actions: сборка Windows тратит их быстрее всего, поэтому `weekly-build` запускается раз в неделю, а кэш vcpkg включён.
