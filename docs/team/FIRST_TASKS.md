### Часть 1 — ядро боя (G1)
1. Библиотека `game/combat` (цель `han_combat`), без зависимости от рендера и Jolt. Всё общение с миром — через `ICombatWorld` (лучи/капсулы, позиции, импульсы).
   Пока интерфейса A нет — набросай `ICombatWorld` в `game/combat/include/` и предложи в `contracts/` отдельным PR (метка `contract`) — A реализует.
2. Формат данных: `MoveData` по примеру из `docs/design/64_…` и части 25. Схема JSON — `contracts/schemas/move.schema.json` (PR с меткой `contract`).
   Загрузчик с валидацией; приёмы бокса (хотя бы 15 штук из базы части 25) в `data/combat/moves/boxing_*.json`.
3. Кадровая машина: startup / active / recovery, окна отмены, буфер ввода, состояния бойца (стойка, движение, атака, блок, уклон, оглушение, падение).
4. Разрешение попаданий на абстрактной геометрии (капсулы/отрезки без Jolt): зоны головы/корпуса/ног, сторона и угол удара, дистанция, удар в движении.
5. Защита: блок, парирование, уклон, сайд-степ, оттеснение — таблица исходов из части 22; стамина и баланс; урон и реакции по направлению.
6. Консольный симулятор `game/combat/tools/combat_sim`: сценарий JSON «два бойца, список действий по кадрам» → лог кадров и итог.
7. Тесты в `tests/combat/` (doctest): ≥ 100 тестов на кадры, окна отмены, исходы блока, стамину.
8. `docs/arch/B.md`: слои боя, поток событий, формат данных; события боя (`HitEvent`, `BlockEvent`, `KnockdownEvent`…) — PR в `contracts/` для A.
9. Критерий: бокс «играется» в симуляторе, тесты зелёные.
