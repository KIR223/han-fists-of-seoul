# Этап 02 — чёткая картинка и безопасные исправления рендера (faf23442)

Ветка `a/faf23442-city-02-sharpness`, зависит от этапа 01 (PR #68). Замеры сделаны на RTX 5060 Ti, 1920×1080 @ 120 Гц, масштаб Windows 100%; замер на RTX 2050 и вашем экране делает владелец (команда в конце).

## Проблема и порядок проверки

Замечание владельца: «размытая картинка» (D08 этапа 01 — была гипотезой). Проверялись по плану: (1) фактическое внутреннее разрешение, (2) TAA, (3) мипы, LOD bias, анизотропия, цветовое пространство, (4) только затем — резкость. Фильтр резкости поверх не добавлялся.

## 1. Внутреннее разрешение, окно, swapchain, масштаб Windows

Добавлена диагностика: демо печатает и пишет в JSON строку `разрешение: окно … пиксели окна … цель рендера … плотность пикселей … масштаб дисплея …` (`Window::logicalSize/pixelDensity/displayScale`, `Renderer::renderExtent`).

- На этом ПК окно 960×540 / 1280×720 / 1920×1080 = пиксели окна = цель рендера = размер PNG, плотность 1,00, масштаб 1,00. Масштаба рендера и двойного масштабирования в коде нет.
- Версия «Windows растягивает картинку при масштабе 125–150%» **опровергнута по документации SDL3** (версия из vcpkg, `docs/README-highdpi.md`): на Windows размер окна всегда в физических пикселях, `SDL_GetWindowPixelDensity()` = 1,0, флаг `SDL_WINDOW_HIGH_PIXEL_DENSITY` на Windows ничего не меняет. Окно создаётся без этого флага — это корректно и менять не нужно.
- **Не проверено на ПК владельца:** на его ноутбуке масштаб Windows больше 100%, но размер окна у демо фиксированный 1280×720, поэтому на экране 1920×1080 картинка идёт 1:1 без растяжения; если окно развёрнуто — цель рендера следует за `SDL_GetWindowSizeInPixels` каждый кадр. Проверка — одна строка вывода демо (ниже).

## 2. TAA: причина мягкости найдена и измерена

**Метод.** Эталон — тот же кадр в 2 раза большем разрешении (1920×1080), усреднённый блоками 2×2 до 960×540. Метрики по яркости (`han/tools/pipeline/image_sharpness.py`, 4 теста): `gradient_ratio` — энергия градиента кадра к эталону (1 — как у эталона, <1 — размытие, >1 — ступеньки или перешарп), PSNR — близость к эталону. Камера, час, трафик, толпа одинаковы (`--deterministic --no-capture`), кадры сняты на 300-м кадре; в движении — пролёт камеры `--fly 1400 280 30` из `(700, 2, 280)`.

**Причина (доказана измерением).** В `shaders/taa.frag` история читалась **билинейно** (`texture(uHistory, prevUv)`): при любом сдвиге камеры каждый кадр усредняет соседние пиксели, а накопление с весом 0,9 копит это размытие. Остальные кандидаты: семплеры (анизотропия 16, трилинейная фильтрация, `mipLodBias` 0, альбедо sRGB) проверены чтением кода и менять не нужно; джиттер задан в пикселях и переводится в NDC делением на размер цели; история сбрасывается при смене размера (`renderer.cpp:544`).

| Кадр | gradient_ratio | PSNR, дБ |
|---|---|---|
| Статика, TAA выключен | 2,164 (ступеньки) | 32,64 |
| **Статика, TAA, билинейная история (было)** | 0,954 | 38,65 |
| Статика, TAA, Catmull-Rom (стало) | 1,088 | 38,34 |
| Движение, TAA выключен | 1,313 (ступеньки) | 38,53 |
| **Движение, TAA, билинейная история (было)** | **0,721** (−28% высоких частот) | 37,59 |
| **Движение, TAA, Catmull-Rom (стало)** | **0,827** | **37,94** |

Значения воспроизведены повторно на отдельно проверенных сборках (хэши exe различаются у «было» и «стало»).

**Исправление.** `sampleHistorySharp` в `taa.frag`: бикубический фильтр Catmull-Rom по сжатому цвету (5 выборок вместо 1, угловые отброшены, веса нормируются); отсечение истории по окрестности 3×3 в YCoCg осталось. Перекомпилировано `python shaders/compile_shaders.py` (glslc из Vulkan SDK 1.4.363.0, результат для нетронутых шейдеров совпал с закоммиченным), в Git изменён только `han/render/generated/taa_frag.h`.

**Побочные эффекты (проверены).**
- Мерцание: средний модуль разности соседних кадров на статичной камере 0,174 → 0,179 из 255, доля пикселей с разностью >8: 0,264% → 0,285% — в пределах шума, новых шлейфов и ореолов на кадре движущегося прохожего и вывесок нет (сравнение «было / стало / эталон», `build/metrics/sharp/compare_move.png`).
- Статический кадр немного «перешарплен» относительно эталона (1,09; PSNR −0,3 дБ): отрицательные лепестки Catmull-Rom. Динамический выигрыш +0,35 дБ и +15% высоких частот перевешивает; при жалобах на звон можно уменьшить вес истории или перейти на смесь с билинейной.
- Стоимость: разность «всего GPU − тени − сцена» 0,11–0,13 мс против 0,10–0,13 мс — около +0,02–0,03 мс (шум запусков ±3%). Память не менялась.

## 3. Прочие проверки без изменений кода

- Анизотропная фильтрация и мипы: у всех материальных семплеров `maxAnisotropy = min(16, лимит GPU)`, `mipmapMode = LINEAR`, `maxLod = CLAMP_NONE`, `minLod = 0` (`renderer.cpp:959–967`); у цели HDR отдельный семплер без мипов — по назначению. Отрицательное смещение LOD не нужно: после исправления статика не мягче эталона.
- Цветовое пространство: альбедо в sRGB-формате, нормали/шероховатость — линейные (по комментариям шейдера и конвейеру); ориентация осей карт нормалей **визуально не проверялась** — относится к этапу 07.
- Bloom, дымка, экспозиция не менялись; дымку города не убирали.

## 4. Слой валидации Vulkan и воспроизводимость

Установлен Vulkan SDK 1.4.363.0 (winget). **Слой валидации теперь загружается** (`слой валидации: включён`): ошибки валидации 0, предупреждение 1 — сообщение загрузчика о дубликате слоя `VK_LAYER_WEOBS_HOOK` (захват OBS), к движку не относится. Утверждения «0 ошибок» из отчётов этапов 00 и 01 были получены **без** слоя и ничего не доказывали; теперь это проверено. Заодно закрыт пункт D12 этапа 01 в части слоя валидации (VRAM по-прежнему не измеряется).

## Регрессия

Графические регрессии не охватывали TAA в движении: у неподвижной камеры история берётся ровно по пикселю, и билинейная выборка совпадает с бикубической. Добавлены:
- `han_scene_demo --drift м/с` (боковой снос камеры) и сцена `taa_motion` в `tests/engine/screenshots/run.py`, эталон `golden/taa_motion.png` (LFS, 163 КБ, снят на RTX 5060 Ti);
- индивидуальный допуск этой сцены `(0,12; 0,0004)` вместо общего `(1,0; 0,004)`: старый шейдер даёт на ней отличие 0,28/255 — общий допуск его бы пропустил. Проверено: со старым шейдером тест падает, с новым проходит.

**Ограничение:** допуск подобран на одной видеокарте; на RTX 2050 возможно ложное срабатывание — тогда посмотреть diff-кадр и пересоздать эталон `--scene taa_motion --update` осознанно. Остальные десять эталонов не обновлялись и совпали в допуске (средние отличия 0,007–0,38 из 255, раньше около 0,003): они сняты с неподвижной камерой, где фильтр теоретически не должен ничего менять, поэтому причина этих малых отличий (вероятно, численный шум повторной проекции) не исследовалась.
